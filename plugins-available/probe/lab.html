Plugin lab

Every action below hits a store plugin seam. Mail and payment rails are not called — they write to the logs table at the bottom.

1. Form → filter + event

Submit is stored, then form.submitted logs a would-be email. Use halt@ or the checkbox to test a filter halt.

2. Quote (car finance)

Server re-runs the quote. The deposit is what would be charged — not the monthly preview.

3. Charge (no rail)

Resolves amount from preset, form field, or quote, opens an order, logs instead of PayHero. Optionally marks paid to fire order.paid.

4. Webhook + job

Inbound /plugins/probe/webhooks/probe, and the heartbeat job (install/import stand-in).

5. Import WooCommerce (different schema)

Woo speaks publish + "29.50" + categories. Dukafi speaks active + cents + collections. The plugin maps; the host writes through CommerceWrites. The Woo GET is logged, not fetched.

6. Extra product / variant fields

Core stays title, price, stock. A plugin registers extras — make, origin, mileage — stored on the row, bindable as currentEntry.fields or {currentEntry.origin}.

Logs table

Host table plugin_logs. This is the stand-in for SMTP and payment APIs.
